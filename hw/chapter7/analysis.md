# OSTEP 第 7 章作业解答：CPU 调度（FIFO / SJF / RR）

对应《操作系统导论》（Operating Systems: Three Easy Pieces）第 7 章 Homework (Simulation)。使用官方模拟器 `scheduler.py`（来源：`remzi-arpacidusseau/ostep-homework` 仓库 `cpu-sched` 目录）在 Linux（WSL Ubuntu，python3）上实际运行验证，**所有数值均取自真实模拟输出**（见 `data/` 目录）。

## 指标定义

- **响应时间（Response Time）**：作业从到达到首次被调度的时间，T_response = T_firstrun − T_arrival
- **周转时间（Turnaround Time）**：作业从到达到完成的时间，T_turnaround = T_completion − T_arrival
- **等待时间（Wait Time）**：作业处于就绪但未运行的总时间

## 第 1 题：三个长度为 200 的作业，SJF 与 FIFO

命令：`python3 scheduler.py -p FIFO -l 200,200,200 -c` 与 `python3 scheduler.py -p SJF -l 200,200,200 -c`

**答案：FIFO 与 SJF 的结果完全相同——平均响应时间 200.00，平均周转时间 400.00，平均等待时间 200.00。**

原因：三个作业长度全部相等（200）。SJF 按长度排序后，作业顺序与 FIFO 完全相同（都是作业 0、1、2），因此执行轨迹与各项指标逐一对齐：三个作业分别在 t=0、200、400 开始，在 t=200、400、600 完成。

模拟器输出（data/q1_fifo_sjf.txt）：

```
FIFO:  Job 0 -- Response: 0.00  Turnaround 200.00  Wait 0.00
       Job 1 -- Response: 200.00  Turnaround 400.00  Wait 200.00
       Job 2 -- Response: 400.00  Turnaround 600.00  Wait 400.00
       Average -- Response: 200.00  Turnaround 400.00  Wait 200.00
SJF:   （与 FIFO 完全相同）
```

## 第 2 题：长度为 100、200、300 的作业，FIFO 与 SJF

命令：`python3 scheduler.py -p FIFO -l 100,200,300 -c` 与 `python3 scheduler.py -p SJF -l 100,200,300 -c`

**答案：FIFO 与 SJF 仍然完全相同——平均响应时间 133.33，平均周转时间 333.33，平均等待时间 133.33。**

原因：作业长度列表 100,200,300 已经按升序排列，SJF 排序后不改变作业顺序（仍是作业 0、1、2），执行轨迹与 FIFO 一致：作业在 t=0、100、300 开始，在 t=100、300、600 完成。

模拟器输出（data/q2_fifo_sjf.txt）：

```
FIFO/SJF: Job 0 -- Response: 0.00    Turnaround 100.00  Wait 0.00
          Job 1 -- Response: 100.00  Turnaround 300.00  Wait 100.00
          Job 2 -- Response: 300.00  Turnaround 600.00  Wait 300.00
          Average -- Response: 133.33  Turnaround 333.33  Wait 133.33
```

## 第 3 题：同样的作业（100,200,300）改用 RR，时间片为 1

命令：`python3 scheduler.py -p RR -q 1 -l 100,200,300 -c`

**答案：平均响应时间骤降至 1.00，但平均周转时间恶化到 465.67（平均等待时间 265.67）。**

原因：RR 以 1 个时间单位轮流运行三个作业，第二个作业在 t=1 首次运行、第三个在 t=2 首次运行，响应时间极佳；但作业 0 要到 t=298 才完成、作业 1 到 t=499、作业 2 到 t=600，周转时间被拉长，比 FIFO/SJF 的 333.33 还差。

模拟器输出（data/q3_rr.txt）：

```
Job   0 -- Response: 0.00  Turnaround 298.00  Wait 198.00
Job   1 -- Response: 1.00  Turnaround 499.00  Wait 299.00
Job   2 -- Response: 2.00  Turnaround 600.00  Wait 300.00
Average -- Response: 1.00  Turnaround 465.67  Wait 265.67
```

**三题对照（负载 100,200,300）**：FIFO/SJF 平均响应 133.33、周转 333.33；RR(q=1) 平均响应 1.00、周转 465.67。这正是"性能（周转时间）与公平/交互性（响应时间）不可兼得"的体现：SJF 优化周转时间但响应时间差，RR 优化响应时间但周转时间差。

## 第 4 题：SJF 与 FIFO 周转时间相同的工作负载类型

**答案：当作业长度列表已经按非递减顺序（升序）排列时——包括所有作业长度相等的情况——SJF 与 FIFO 的周转时间完全相同。**

原因：SJF 只是把作业按长度升序排列后依次运行；如果原列表本来就是升序（或全部等长），排序不改变执行顺序，SJF 的执行轨迹与 FIFO 一致，每个作业的开始与完成时间相同，故各项指标完全相同。

模拟验证（data/q4_sjf_vs_fifo.txt）：

- 等长负载 `-l 10,10,10`：FIFO 与 SJF 平均周转均为 20.00（相同）
- 已升序负载 `-l 100,200,300`：FIFO 与 SJF 平均周转均为 333.33（相同）
- 反例 `-l 300,100,200`：FIFO 平均周转 433.33，SJF 平均周转 333.33（不同——SJF 先跑最短作业，明显更优）

## 第 5 题：SJF 与 RR 响应时间相同的工作负载与时间片

**答案：当所有作业长度相等（设为 L）且时间片恰好等于该长度（q = L）时，SJF 与 RR 的响应时间逐作业相同。**

原因：q = L 时，每个作业都在自己的第一个时间片内完成，RR 无需抢占，运行顺序退化为与 SJF 相同（0、L、2L、…），因此每个作业的首次运行时间（响应时间）完全相同。

模拟验证（data/q5_sjf_vs_rr.txt）：

- `-l 10,10,10` SJF：平均响应 10.00（各作业 0、10、20）
- `-l 10,10,10` RR q=10：平均响应 10.00（各作业 0、10、20）——相同 ✓
- 反例 1：`-l 10,10,10` RR q=1：平均响应 1.00（各作业 0、1、2）——不同
- 反例 2：`-l 10,20,30` RR q=10：平均响应 10.00（各作业 0、10、20）；而 SJF 为 0、10、30（平均 13.33）——不同

## 第 6 题：SJF 的响应时间随作业长度的变化趋势

**答案：SJF 的平均响应时间随作业长度线性增长。** 对 N 个等长 L 的作业，平均响应时间 = (0 + L + 2L + … + (N−1)L)/N = L·(N−1)/2；三个作业时即等于 L。作业越长，排在后面的作业等待前面作业完成的时间越久。

模拟验证（data/q6_sjf_trend.txt，均为 `-p SJF -l L,L,L -c`）：

| 作业长度 L | 平均响应时间 | 平均周转时间 |
| --- | --- | --- |
| 10 | 10.00 | 20.00 |
| 100 | 100.00 | 200.00 |
| 1000 | 1000.00 | 2000.00 |

平均响应时间随 L 从 10→100→1000 线性增长为 10→100→1000，趋势与公式 (0+L+2L)/3 = L 完全吻合。

## 第 7 题：RR 的响应时间随时间片的变化趋势与最坏情况公式

**答案：RR 的平均响应时间随时间片长度线性增长。** 对 N 个作业（长度均不小于时间片），平均响应时间 = q·(N−1)/2；**最坏情况响应时间公式为 T_response,worst = (N−1)·q**——排在最后的作业要等其他 N−1 个作业各完整运行一个时间片后才首次被调度。

模拟验证（data/q7_rr_quantum.txt，均为 `-p RR -q Q -l 10,10,10 -c`）：

| 时间片 q | 平均响应时间 | 平均周转时间 |
| --- | --- | --- |
| 1 | 1.00 | 29.00 |
| 5 | 5.00 | 25.00 |
| 10 | 10.00 | 20.00 |

平均响应时间随 q 从 1→5→10 线性增长为 1→5→10，与公式 (0+q+2q)/3 = q 吻合；最坏情况（第三个作业）响应分别为 2、10、20 = (N−1)·q。注意时间片增大后 RR 越来越像 FIFO/SJF：q=10 时周转时间降到 20.00，与 FIFO 相同。

## 结论

1. **SJF 优化周转时间**：最短作业优先，能显著降低平均周转时间（如 300,100,200 负载：433.33 → 333.33），但对响应时间不友好（排在后面的作业等待时间长）。
2. **RR 优化响应时间**：小时间片让每个作业迅速首次运行（如 100,200,300 负载 q=1：平均响应 133.33 → 1.00），但把作业"拉长"完成，周转时间变差（333.33 → 465.67）。
3. **时间片是关键权衡参数**：时间片越短响应越好但上下文切换开销越大；时间片越长（趋于 FIFO）周转越好。最坏响应 = (N−1)·q，平均响应 = q·(N−1)/2。
4. **工具使用要点**：用 `-l` 指定负载、`-p` 选择策略、`-q` 设置 RR 时间片，加 `-c` 查看全部指标；用 `-s` 种子可复现随机负载。
